ЖУРНАЛ ПОСЕЩАЕМОСТИ 3.3 — ПУБЛИКАЦИЯ НА GITHUB PAGES

В этой папке рабочая версия без демонстрационных учеников и без токенов.
Файлы: index.html, version.json, .nojekyll. Сборка на GitHub не требуется.

ПЕРВАЯ ПУБЛИКАЦИЯ
1. Создайте репозиторий на GitHub.
2. Загрузите СОДЕРЖИМОЕ этой папки в корень репозитория:
   index.html, version.json и .nojekyll. Не загружайте ZIP как один файл.
3. Откройте Settings → Pages → Build and deployment.
4. В Source выберите Deploy from a branch, ветку main и папку / (root).
5. Нажмите Save. Дождитесь завершения публикации и откройте адрес,
   который покажет GitHub. Обычно это https://ИМЯ.github.io/РЕПОЗИТОРИЙ/.
6. Откройте этот же адрес на телефоне и компьютере.

ПОДКЛЮЧЕНИЕ ОБЩЕГО ЖУРНАЛА
GitHub Pages размещает интерфейс. Общие записи хранятся отдельно в Gist.
1. В старом журнале нажмите «Скачать копию» и сохраните JSON.
2. На https://gist.github.com/ создайте Secret Gist с именем attendance.json
   и содержимым {"version":5,"students":[],"attendance":{},"settings":{}}.
   Если общий Gist уже есть, используйте его — новый создавать не нужно.
3. Создайте отдельный GitHub Personal Access Token (classic) с правом gist:
   https://github.com/settings/tokens/new. Он должен иметь доступ к этому Gist.
4. На сайте нажмите «Подключить устройства», вставьте токен и ID/ссылку Gist,
   затем «Сохранить подключение».
5. На остальных устройствах укажите ТОТ ЖЕ Gist и токен с доступом к нему.
   Имена репозиториев Pages сами по себе не связывают журналы.
6. При переносе с локального HTML на сайт восстановите JSON через кнопку
   версии → код 020912 → «Загрузить копию» на ОДНОМ устройстве, подключите
   синхронизацию и дождитесь «Все изменения отправлены». На новых устройствах
   журнал загрузится из Gist автоматически — импортировать JSON повторно не нужно.

Токен вводится в интерфейсе, не в исходниках. Не загружайте резервные JSON
с учениками, токены и файлы attendance.device.*.json в репозиторий Pages.
Токен хранится в текущей сессии вкладки: после её закрытия введите его заново.
До подключения очередь сохраняется локально. Secret Gist доступен по ссылке;
он не заменяет сервер с персональными учётными записями и правами доступа.

ОБМЕН ИЗМЕНЕНИЯМИ
Правка ставится в очередь сразу; автоматическая отправка запускается после
400 мс без новых правок. Активная вкладка проверяет сервер каждые 5 секунд.
При возвращении к вкладке или восстановлении сети проверка запускается сразу.
Фоновая или закрытая вкладка не гарантирует работу: мобильный браузер может
приостановить её. При ограничении частоты GitHub показан срок следующей попытки.

При получении обновлений показаны время, число записей и первые изменённые
записи; дневные отметки подсвечиваются. Открытое занятие обновляется сразу.
Конфликт двух независимых правок одной записи требует выбора в очереди.
Остальные полученные записи отображаются даже при таком конфликте.

ОБНОВЛЕНИЕ САЙТА
Заменяйте index.html и version.json вместе, сохраняя адрес сайта.
Открытая версия 3.3 проверяет новую сборку раз в 5 минут и при возвращении
к вкладке (не чаще раза в 5 минут). Появляется кнопка «Обновить приложение»:
она сохраняет журнал и загружает страницу с новым параметром версии.
Для первого перехода с 3.1 обновите страницу вручную после публикации.
Локальные данные остаются в браузере по прежнему адресу. Перед обновлением
сохраните JSON; при смене домена/браузера восстановите его на новом адресе.

ДЛЯ ОФЛАЙН-РАБОТЫ
Сохранённый автономный HTML можно открыть без интернета. На Pages не добавлен
сервис-воркер: первая загрузка сайта и повторное открытие без сети не гарантируются.
Уже открытая страница сохраняет правки локально и отправляет их после подключения.

ДИЗАЙН 3.3
Боковая навигация на компьютере и нижняя панель на телефоне. Новый журнал
открывается в режиме «Неделя» на компьютере и «День» на телефоне; ранее
выбранный вид сохраняется. Поле имени на телефоне раскрывается по «+ Ученик».
